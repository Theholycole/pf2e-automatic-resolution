# Native support for ongoing spell effects

Research date: 2026-09-19. Planning evidence only; no running-world behavior was tested.

## Evidence boundary

The module baseline declares Foundry v14 / PF2e 8.5.0 ([BASELINE.md](../../BASELINE.md)). Module inspection used commit `92b4fd488f4d73eeed74ad77a78a65411e28bb47`. Exact upstream tag `pf2e-8.5.0` sources were inspected for Effect, AbstractEffect and EffectTracker; the GitHub source-tree index confirms the additional source paths listed below. The baseline's external local PF2e checkout is unavailable at its recorded path. The user subsequently supplied `/run/media/theholycole/Bigger Local Disk/PF2e Notes/pf2e`; inspection found extracted content directories, not runtime TypeScript or a Git checkout. It therefore does not supply the remaining runtime sources. Broader archive retrieval was declined; no alternative bulk acquisition was attempted.

Foundry documentation inspected reports **14.365 Stable**. This verifies v14 API availability in that documented build, not the unspecified patch build used by the module baseline. Negative claims below mean “not established by inspected sources,” not proof that no native capability exists.

## Bounded follow-up experiment

Prerequisites: disposable Foundry v14/PF2e 8.5.0 world, recorded Foundry patch number and PF2e automation settings, module at a recorded commit, two GM clients plus one player, encounter with two linked tokens and two unlinked copies, a timed native Effect with an effect-ended successor, and a condition wrapper. Record document UUIDs, world time, round/turn, primary updater, active GM, and observed Item/combat/time hooks.

1. Expire the Effect by turn and world time with remove-effects both enabled and disabled. Observe effect rule suppression, document deletion/update, successor prompting and exactly-once behavior. Repeat across a reload and backward time change. **This is the first experiment required to select a reliable expiry integration seam.**
2. Interrupt before/after the expiry transition and move GM authority. Verify existing module state is recoverable or visibly requires review; do not automatically replay uncertain mutations.
3. Check source/target anchoring, cast-wide dismissal, condition cascades and token identity cases from the matrix.
4. Once candidate recurring/Sustain/aura workflows are specified, test native event availability against those exact workflows. This research does not choose those workflows.

## Remaining source work and closure assessment

The question is sufficiently answered to inform discussion of ownership: native Effects provide storage, time-based expiry and rule suppression; the module has one-shot persisted resolution plus Effect transitions, but still needs durable ongoing-spell orchestration. **It is not sufficient to close a stronger claim that all baseline lifecycle API behavior has been established.** If closing this research ticket, record its limited source coverage and carry the expiry integration experiment and remaining source inspection explicitly into the next decision's prerequisites.
